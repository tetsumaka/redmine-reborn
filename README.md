# Redmine Reborn

Кроссплатформенное Electron-приложение на TypeScript и React для локального учёта и отправки времени в Redmine. Renderer собирается через Vite.

## Запуск

### Linux / WSL

Перед первым запуском установите системные библиотеки Electron:

```bash
sudo apt-get update
sudo apt-get install -y libnss3 libnspr4 libatk1.0-0 libatk-bridge2.0-0 \
  libcups2 libgtk-3-0 libpango-1.0-0 libcairo2 libxcomposite1 \
  libxdamage1 libxfixes3 libxrandr2 libgbm1 libxkbcommon0 \
  libasound2 libatspi2.0-0
```

Для запуска окна из WSL необходим WSLg (Windows 11) либо настроенный X-сервер.
Команда `npm start` автоматически очищает `ELECTRON_RUN_AS_NODE` и добавляет
необходимые для WSL флаги Chromium. Запускайте её из обычного WSL-терминала:

```bash
npm install
npm start
```

Для разработки с автоматической пересборкой:

```bash
npm run dev
```

Перед `npm run dev` и `npm start` автоматически выполняется `install-electron`.
Это необходимо для Electron 42: `npm install` больше не скачивает бинарник,
а `electron-vite` ожидает, что он уже установлен. При первом запуске бинарник
скачивается или распаковывается из локального кэша; при следующих запусках
установщик проверяет наличие нужной версии.

## Сборка установщика

```bash
npm run dist:linux  # AppImage и DEB
npm run dist:win    # Portable EXE
npm run dist:mac    # DMG
```

`npm run dist` остаётся алиасом для Linux-сборки. Установщик macOS рекомендуется собирать на macOS; переносимый Windows EXE можно создать из Linux/WSL без установленного Wine.

## Аналитика

Для выбранного месяца доступны отдельные вкладки: редактирование и синхронизация записей, составной график времени по дням, рейтинг задач по трудозатратам и обзор распределения времени по активностям.

## Настройка Redmine

1. Укажите базовый URL Redmine, API-ключ и ID пользователя.
2. Выберите один CA-сертификат (`.pem`, `.crt` или `.cer`).
3. Заполните числовые ID видов деятельности из раздела Redmine «Администрирование → Учёт времени → Виды деятельности».
4. Для таблиц кодревью и QA на «Главной» проверьте раздел «Фильтры главной страницы». По умолчанию используются поля «Кодревьювер» — `6`, «QA» — `2` и статусы Code Review — `11`, Resolved — `3`, Feedback — `13`. Их можно изменить; вариант «По названию» определяет статус автоматически.

Данные хранятся локально в каталоге `userData` Electron. Сертификат не копируется: приложение сохраняет путь к выбранному файлу и передаёт его как `ca` HTTPS-агенту только в главном процессе.

## Пользовательские фильтры

Во вкладке «Главная → Мои задачи» в правой части заголовка каждой таблицы есть шестерёнка. Она открывает диалог выбора колонок и их порядка с той же формой, что используется при создании фильтра. Доступны штатные поля Redmine: название, приоритет, исполнитель, статус, трекер, проект, версия, родительская задача и её тема, автор, категория, даты начала, завершения, создания, обновления и закрытия, трудозатраты и оценки времени (в том числе общие), готовность, последний изменивший, связанные задачи и файлы. Номер задачи всегда первый. Отсутствующие или недоступные по правам значения отображаются прочерком; нулевые часы и готовность показываются как `0 ч` и `0%`. Родительские задачи, связи и файлы доступны по ссылкам.

Тема родительской задачи, последний изменивший, связи и файлы загружаются дополнительно только при выборе соответствующих колонок. Для тем родителей запросы объединяются, а для последнего изменившего загружается видимая история задачи. Изменение выбора этих колонок обновляет данные; простая перестановка не запускает повторную загрузку. Настройки сохраняются отдельно для каждой таблицы и восстанавливаются после перезапуска. Чтобы вернуть стандартный набор, снимите флажок «Настроить колонки и их порядок» и сохраните. Кнопка «Отмена» закрывает диалог без применения изменений.

Во вкладке «Главная → Фильтры» можно создавать, редактировать и удалять локальные фильтры. В форме выбираются доступный проект, статус, трекер, приоритет, автор, исполнитель, категория, Quality Assurance, Code Reviewer, родительская задача, целевая версия, текст в названии задачи и условие «я — наблюдатель». Для автора, исполнителя, QA и кодревьювера доступны участники проекта и вариант «Я». Номер родительской задачи ограничивает результаты её непосредственными подзадачами. Для категории и целевой версии можно указать конкретное значение, отсутствие значения или любое заполненное значение. Все выбранные условия применяются одновременно. Справочники и участники выбранного проекта загружаются из Redmine; для ролей кодревьювера и QA используются ID полей из настроек. Существующие условия «я — автор/кодревьювер/QA» восстанавливаются при редактировании.

В поле «Группировать результаты по» доступны стандартные группировки Redmine: по проекту, трекеру, статусу, приоритету, автору, исполнителю, категории, целевой версии, датам и готовности. По умолчанию результаты не группируются. Выбранная группировка сохраняется вместе с фильтром.

В блоке «Колонки результатов» можно включить настройку колонок, добавить нужные, убрать лишние и менять порядок кнопками со стрелками. Доступны те же штатные колонки Redmine, что и в «Моих задачах». Колонки, добавленные администраторами или плагинами (оценка QA, теги, Merge request, порядок выполнения, «Вызвано задачей», Story point), не предлагаются. Ранее сохранённые пользовательские колонки фильтров сохраняются при редактировании. Номер задачи всегда остаётся первым. Выбор и порядок сохраняются при редактировании и после перезапуска приложения. Если настройка выключена, используются колонки по умолчанию в Redmine, в том числе для ранее созданных фильтров.

Название фильтра используется только для отображения. Ссылка в таблице открывает задачи выбранного проекта с настроенными условиями, группировкой и колонками в браузере. Фильтры хранятся в локальном `data.json` и сохраняются после перезапуска приложения.

## События

Во вкладке «Главная → События» отображается история изменений за выбранный день: новые события сверху, старые снизу. Выбор дня и стрелки работают так же, как в «Записях времени». День определяется в локальном часовом поясе. Список загружается при открытии вкладки, смене дня и нажатии «Обновить события», без периодического опроса.

Используются те же тексты и типы событий, что в десктопных уведомлениях: назначение задачи, комментарии, упоминания и смена статуса, включая закрытие. В колонке «Событие» имя показывается без `@`, а номер задачи в конце сообщения открывает соответствующее изменение в Redmine. Колонка «Название» расположена после события и показывает полное название без ограничения длины. Собственные действия и изменения, сделанные в закрытом статусе, не показываются; события до закрытия сохраняются в истории выбранного дня. Источники — задачи, назначенные вам или отслеживаемые вами сейчас, и задачи с упоминаниями вашего логина. Поэтому история может быть неполной для задач, которые раньше были назначены вам или отслеживались вами, а сейчас уже нет.

История доступна и при отключённых десктопных уведомлениях, в том числе за дни, когда приложение не работало. Просмотр истории не показывает всплывающие уведомления. Если часть историй загрузить не удалось, раздел сообщает об этом и показывает остальные события.

## Уведомления

В «Настройки → Уведомления» можно отключить проверку изменений, изменить интервал опроса (по умолчанию 60 секунд), выбрать один из четырёх углов экрана и показать тестовое уведомление. Приложение проверяет открытые задачи: назначенные вам, отслеживаемые вами (где вы наблюдатель) и задачи с упоминаниями вашего логина в комментариях. Для отслеживаемых задач приходят уведомления о комментариях и смене статуса, даже если задача назначена другому пользователю. Дополнительно проверяются недавние закрытия этих задач, чтобы показать событие перехода из открытого статуса в закрытый. Комментарии, упоминания и другие изменения в уже закрытых задачах не показываются; после переоткрытия задачи обычные уведомления возобновляются. Собственные действия не показываются. Проверка работает и при свёрнутом окне; после полного выхода из приложения она прекращается.

Уведомления сообщают о комментарии, назначении на вас, упоминании, переоткрытии, закрытии, начале тестирования и других изменениях открытого статуса. Если одна запись истории удовлетворяет нескольким условиям, показывается одно сообщение «обновил задачу». Исключение — закрытие: сообщение всегда содержит «закрыл задачу», в том числе при одновременном комментарии. Закрытие определяется по признаку `is_closed` статуса Redmine, поэтому поддерживаются и статусы с другими названиями. Номер задачи ведёт к соответствующей записи истории, а название в теле ограничено первыми 100 символами с многоточием при превышении. Под названием отображается комментарий, если он есть: до 200 символов с многоточием при превышении, максимум две строки в отдельном блоке.

Одновременно отображается до трёх уведомлений в отдельном окне поверх рабочего стола, по умолчанию справа снизу. Это собственные уведомления приложения; в центр уведомлений ОС они не добавляются. Каждый запуск начинает отслеживание с момента открытия приложения: уведомления за время, когда приложение было закрыто, не показываются. После отключения и повторного включения отслеживаются только новые события. Изменение интервала и положения не сбрасывает время последней проверки.
